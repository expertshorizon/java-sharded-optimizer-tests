There's a Java training-log replay simulator in `/app` that reconstructs sharded optimizer state from asynchronous submissions. Repair its logic in place: keep Java sources under `/app/src/main/java`, keep `com.trainingsim.Main` as the entry point, and do not change CLI flags or JSON field names. Results must be deterministic and all arithmetic must remain exact rational, never floating point. Numeric strings may be decimals, scientific notation, or `p/q` fractions with a sign on either component, wherever they appear: in the config, in a log event's gradient, and in the parameters, momentum, and pending gradients of a checkpoint read through `--checkpoint-in`. Raw `NaN`, `Inf`, `+Inf`, or `-Inf` gradient tokens poison a submission. Every rational value written to `--out` or `--checkpoint-out` must be rendered as `numerator/denominator` in lowest terms with a strictly positive denominator (e.g. `-1/5`, `2/1`, never `1/-5` or `2/10`).

The frontier is `committed_step + 1`. Only frontier steps may resolve, and lookahead exactly equal to `max_staleness` is admissible; only larger lookahead is stale. Within a step, retain the first accepted contribution per worker: repeats are `duplicate`, even when the bucket is full, while new workers on a full bucket are `superfluous`. If any accepted contribution in a quorum is poisoned, skip the optimizer update but still advance the frontier. Otherwise average the quorum, clip that averaged gradient once using the L1 norm of the averaged gradient vector, then apply the existing momentum/update rule.

Output shards must cover the vector contiguously and as evenly as possible; earlier shards receive remainder elements. Checkpoints preserve parameters, momentum, pending buckets, per-step rejections, and cumulative rejection history; trace is fresh per invocation. Pending contributions use the normalized checkpoint shape `{worker_id, step, poisoned, gradient}`. On `--checkpoint-in`, normalize each pending entry before replay: an explicit `poisoned: true` or any raw `NaN`, `Inf`, `+Inf`, or `-Inf` gradient token yields `poisoned: true` with `gradient: null`; otherwise parse the finite gradient using the accepted numeric syntax. Checkpoint output stores finite gradients as canonical rational arrays. A step's per-step rejection entry is cleared the instant that step itself commits — it does not persist alongside the step's resolved state — but a later rejection that still targets that now-committed step number starts a fresh entry for it rather than being dropped; only the cumulative rejection history is guaranteed to retain every record permanently. On resume, drain any already-quorate frontier buckets before classifying tail events.
